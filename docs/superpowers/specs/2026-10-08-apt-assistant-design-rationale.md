## 0. 요약

### 0.1 결정 세 줄

1. **시간 압박부터 재현한다.** 응시 화면의 모양보다 영역별 시간 압박이 먼저다. 가장 먼저 남길 데이터는 문항별 응답 시각이다. 교재 기준 DCAT는 영역마다 제한시간이 따로 있는데(20·10·20·7.5·7.5분), 합격시대 1회에서는 65분 제한에 83분을 썼다.
2. **원본만 저장하고 나머지는 계산한다.** 세션은 이벤트 로그로, 정답과 유형은 세트(교재 범위)에, 합격시대 결과는 붙여넣기 원문과 파싱한 행으로 저장한다. 문항별 정오, 문항 시간, 시간 내 점수, 분석 셀은 조회할 때 계산한다.
3. **기능은 자르되 필드는 자르지 않는다.** v0.1(오늘)은 연습 루프(타이머·도구·OMR·채점·결과·백업)만 만들지만, v0.2 분석에 쓸 원자료는 첫 세션부터 저장한다. v0.2(내일)에 가져오기·태깅·누적 분석을 넣은 뒤 기능을 동결한다.

### 0.3 합격시대 1회를 교재 5영역으로 다시 읽기

결과표의 행 순서가 곧 문항 순서다. 누적 문항 수 20·35·55·65·75는 행 경계와 정확히 맞는다(`exam-facts.md:28-35`, 42행 재계산으로 확인).

| 영역 | 문항 위치 | 정답/문항 | 정답률 |
|---|---|---|---|
| 언어논리 | 1–20 | 15/20 | 75% |
| 언어표현 | 21–35 | 12/15 | 80% |
| 수리자료분석 | 36–55 | 11/20 | 55% |
| 공간추리 | 56–65 | 2/10 | 20% |
| 도형추리 | 66–75 | 6/10 | 60% |

- 공간추리 2/10은 5지선다를 무작위로 찍었을 때의 기대값(20%)과 같다. 그중 58–65번의 0/8(전개도·평면도형 활용)은 무작위로 찍어도 16.8% 확률로 나온다.
- 고르게 풀었다면 65분 시점은 약 59번이다(75×65/83, 추론). 그렇다면 공간추리 대부분과 도형추리 전부를 제한시간 뒤에 풀었다. 같은 구간의 도형추리가 6/10이므로 시간만으로는 설명이 약하다(추론). 그래도 이 데이터만으로 공간추리를 실력 약점으로 확정하지 않는다. 툴의 시간제 세션에서 시간 내 구간과 초과 구간을 나눠 다시 본다.
- 사이트 점수 61.2는 46/75 = 61.33과 다르다. 계산 공식을 모르므로 받은 값만 보관하고 다시 계산하지 않는다.
- 합격시대 1회는 단일 65분 타이머였고 시간 초과를 막지 않았던 것으로 보인다(추론). 영역별 마감은 이 툴에서만 연습할 수 있다.

  - 실전에서 어느 유형을 뒤로 미루거나 찍을지
  - 어느 영역에서 시간이 새는지

### 1.2 설계 원칙

1. 시간 압박 재현이 화면 모양 재현보다 먼저다.
2. 원본만 저장하고 파생값은 계산한다(늦은 결합). 정답·유형·별칭을 고치면 과거 기록이 마이그레이션 없이 바로잡힌다.
3. 시험 규칙은 프로필 설정값으로 두고 출처 배지를 단다. 규칙을 바꾸는 데 코드 수정이 필요하면 설계 결함이다.
4. 숫자키의 의미는 포커스에 따라 바뀌지 않는다. 답은 마우스로 고르고, 숫자키는 계산기나 메모로 간다.
5. 분석의 목적은 판단이다. 표본 크기(x/n)를 항상 함께 보인다.

- 테스트는 Vitest + fake-indexeddb, 그리고 설치된 Chrome에서 돌리는 Playwright(channel `chrome`)로 한다.
- 확인된 실행 환경: Node 24.14.0, npm 11.9.0, Python 3.14.3, Chrome 154.0.8037.98(`C:\Program Files\Google\Chrome\Application\chrome.exe`).

**[충돌] 차트.** brain은 Recharts를 쓰고, 리스크 렌즈는 차트 라이브러리를 빼며, 데이터 렌즈는 v0.1에 차트를 두지 않는다.
→ **권고: Recharts를 빼고, v0.2에 SVG 산점도 1개와 CSS 막대만 둔다.** 필요한 차트는 산점도 하나라서 직접 그려도 60줄 안팎이다. 그만큼 의존성과 구현 패키지 크기가 줄어든다.

**[충돌·경미] IndexedDB 래퍼.** brain은 Dexie를, 리스크 렌즈는 idb-keyval(레코드마다 키)을 골랐다.
→ **권고: Dexie를 유지하되 패널의 규칙을 따른다.** 규칙은 네 가지다. 테이블은 v1에서 한꺼번에 만든다. 기본 키만 두고 보조 인덱스·liveQuery는 쓰지 않는다. 부팅할 때 전부 메모리로 읽는다. 레코드 단위로 쓴다. Dexie를 유지하는 이유는 복원처럼 여러 테이블을 바꾸는 작업을 트랜잭션 하나로 처리할 수 있어서다.

### 2.2 file:// 제약

- 동적 import, Web Worker, 런타임 fetch를 쓰지 않는다. 기본 프로필과 유형 시드는 번들에 넣는다. file://에서는 외부 module 스크립트와 fetch가 막히고 인라인 스크립트는 동작한다(추론, P1에서 확인).
- `crypto.randomUUID`, Web Locks, BroadcastChannel처럼 보안 컨텍스트나 origin에 민감한 API는 기능 감지 뒤에만 쓰고 대체 경로를 둔다. ID 대체: `Date.now().toString(36)` + 난수.
- 부팅할 때 `navigator.storage.persist()`를 요청하고 결과를 설정 화면에 보인다.

### 2.3 실행 창(바로가기)

```
대상: "C:\Program Files\Google\Chrome\Application\chrome.exe"
인수: --user-data-dir="E:\APT assistant\chrome-profile" --no-first-run --no-default-browser-check
      --app="file:///E:/APT%20assistant/app/index.html"
      --window-size=<W>,<H> --window-position=<X>,0
```

- 전용 `--user-data-dir`을 쓰면 메인 프로필에서 사이트 데이터를 지워도 영향이 없고, 다른 file:// 페이지와 저장소가 섞이지 않는다. 별도 프로세스로 뜨므로 창 크기 플래그도 적용된다(추론).
- **기록(IndexedDB)은 `chrome-profile` 폴더에 들어 있다.** 이 폴더를 지우면 기록도 사라진다. 그래서 진짜 보관본은 백업 JSON이다.
- W·H·X는 해상도와 배율로 정한다(부록 B-1). 1920×1080에서 30% 폭은 배율 100%일 때 약 576px, 125%일 때 약 461px이다.
- 바로가기는 `scripts/make-shortcut.ps1`이 바탕화면에 만든다. 경로에 공백이 있으므로 인수를 따옴표로 감싸고 URL에는 `%20`을 쓴다.

### 2.4 릴리스 사본

- 개발 빌드는 `dist/`에만 나온다. `npm run release`는 리뷰 레인이 검증한 빌드만 `app/index.html`로 복사하고, 직전 판은 `app/prev/index.html`에 남긴다.
- 롤백은 prev를 다시 복사하면 된다. 앱이 자기보다 높은 schemaVersion의 데이터를 만나면 쓰기를 멈추고 읽기 전용으로 연다(§12). v0.1로 롤백해도 v0.2 데이터가 망가지지 않게 하려는 장치다.

### 2.5 폴백: 고정 포트 로컬 서버

- P1 프로브에서 창을 다시 열었을 때 file:// IndexedDB가 남아 있지 않으면 `start-apt.cmd` 하나로 두 가지를 함께 띄운다.
  - `python -m http.server 41731 --bind 127.0.0.1 -d "E:\APT assistant\app"`
  - 같은 user-data-dir로 `--app=http://127.0.0.1:41731/`
- origin에는 포트가 포함되므로 포트는 영구 고정한다. file://에서 http로 옮기면 저장소가 달라지므로 기록은 백업·복원으로 옮긴다.

### 2.6 창 운용

- Win+→로 툴 창을 화면 오른쪽에 붙인 뒤 경계를 끌어 e-book 70 : 툴 30으로 맞춘다.
- 키보드 포커스는 툴에 두고 e-book은 마우스 휠로 넘긴다. Windows의 '비활성 창 스크롤'은 기본으로 켜져 있다. 알라딘 뷰어가 휠로 쪽을 넘기는지는 첫날 확인한다(부록 B-6).

## 4. 데이터 모델

### 4.1 저장 원칙

**[충돌] 저장 모델.**
- brain: 문항마다 `QuestionRecord`(answer, correct, isCorrect, timeSec, visits, guessed, flagged, typePath, errorReason, synthetic)를 저장한다. 합격시대 집계 행은 합성 레코드(맞음 k개, 틀림 n−k개)로 저장한다.
- 패널(세 렌즈 공통, 데이터 렌즈가 가장 구체적): 세션에는 타임스탬프가 붙은 이벤트 로그만 저장한다. 정답 키와 유형 범위는 세트에, 합격시대는 원문과 파싱 행으로 저장한다. 문항 정오, 시간, 분석 셀은 조회할 때 계산한다.

→ **권고: 패널안.** brain의 `QuestionRecord`는 저장하지 않는 파생 뷰 `QuestionView`로 바꿔 남긴다. 결과·분석 코드는 brain 설계대로 엔진 하나를 쓴다. 이유는 네 가지다.
1. 시간 내 점수와 랩 시간은 응답 시각이 남아 있어야 나중에 계산할 수 있다.
2. 정답 키 오타나 유형 태그를 고치면 그 세트의 과거 세션이 모두 바로 고쳐진다.
3. 외부 집계의 '틀림'에는 오답과 무응답이 섞여 있다. 이를 합성 오답 레코드로 저장하면 모두 응답한 오답으로 보여 미응답률과 찍음 비율이 오염된다.
4. 문제가 e-book에 있으므로 `visits`(문항 방문 횟수)는 측정할 수 없다. 이 필드는 뺀다.

### 4.2 Dexie 스키마 v1

테이블은 처음에 한꺼번에 만들고 기본 키만 둔다.

| 테이블 | 키 | 내용 |
|---|---|---|
| profiles | id | 사용자 프로필(내장 프로필은 번들이 원천) |
| sets | id | ProblemSet: 교재 범위, 정답 키, 유형 범위 |
| sessions | id | Session: 계획, 이벤트 로그, 메모 |
| imports | id | ImportRecord(v0.2부터 사용하지만 테이블은 v1에 만든다) |
| taxonomy | profileId | 가족·잎 목록(번들 시드 + 사용자 추가) |
| aliases | key | 외부 경로 → 가족·잎 |
| kv | key | settings, meta(schemaVersion, runCount, lastBackupAt), owner(창 잠금 하트비트) |

데이터는 주당 1MB 미만으로 예상하므로(추정) 부팅할 때 전부 읽어 메모리에서 계산한다. 시험 주간에는 IndexedDB 버전 업그레이드를 하지 않는다. 문서 구조가 바뀌면 문서마다 붙은 `schemaVersion`을 `migrate()`로 올린다.

### 4.3 저장 타입

  | { t: number; k: 'sectionStart'; s: number; auto?: boolean }
  | { t: number; k: 'sectionEnd'; s: number; reason: 'deadline' | 'manual' }
  | { t: number; k: 'answer'; q: number; c: number }
  | { t: number; k: 'clear'; q: number }
  | { t: number; k: 'flag'; q: number; on: boolean }

  | { t: number; k: 'gap'; from: number; to: number; cause: 'sleep' | 'closed' }

interface SectionPlan {        // 세션 시작 때 프로필 값을 복사한 스냅샷

  limitSec: number; choices: number; paceSec: number;
}

  id: string; profileId: string; setId: string;

  attempt: number;                         // 같은 세트의 몇 번째 풀이
  plan: SectionPlan[]; events: Ev[];
  status: 'in_progress' | 'awaiting_key' | 'graded' | 'abandoned';
  reasons?: Record<number, 'concept' | 'slip' | 'misread'>;   // v0.2 오답 이유

  raw: { html?: string; text: string }; parserVersion: number;
  header?: { round?: number; date?: string; rank?: number; takers?: number; usedMin?: number;

- 문항 번호 `q`는 세트 안에서 0부터 매기는 순번이다. 화면에 보이는 번호는 `numbering`으로 계산한다. 교재가 영역마다 1번부터 매기는 경우도 처리한다.
- 모든 세션은 세트를 가진다. 이름 없이 시작한 드릴도 '드릴 10/08 15:30' 같은 세트를 자동으로 만든다. 그래야 정답과 유형의 늦은 결합을 한 경로로 처리할 수 있다.
- `Session.plan`은 시작 시점의 영역 정의를 복사해 둔 것이다. 나중에 프로필 값을 고쳐도 과거 세션의 마감 계산은 바뀌지 않는다.

## 5. 타이머 엔진

### 5.1 시간 계산

- 시간의 원천은 이벤트 타임스탬프(`Date.now()`) 하나다.
  - `deadline(s) = start(s) + limitSec×1000 + paused(s, now)`
  - `remaining = deadline − now`
  - 카운터를 1초씩 깎는 방식은 쓰지 않는다.
- `paused`에는 `pause`/`resume` 구간과 `pauseRange` 보정 구간을 모두 넣는다.
- `setInterval(250ms)`는 화면 갱신에만 쓰고, `visibilitychange`·`focus`·`pageshow` 때는 바로 다시 계산한다.
- e-book 창에 가려지면 Chrome이 타이머를 1초, 5분 뒤에는 1분 단위로 늦출 수 있다(추론). 판정은 타임스탬프로 하므로 결과는 달라지지 않는다.
- 시계가 거꾸로 가면(`now`가 마지막 이벤트 시각보다 작으면) 마지막 이벤트 시각으로 고정한다.

### 5.2 마감 정책

**[충돌] 실전 모드를 v0.1에 넣을지.**
- brain과 UX 렌즈: v0.1에 실전(하드 마감)과 연습을 둘 다 넣는다.
- 리스크 렌즈: v0.1은 소프트 마감만 두고, 강제 마감은 v0.2로 미룬다.
- 데이터 렌즈: 소프트 마감(초과 뒤에도 계속)과 두 점수를 요구한다.

→ **권고: v0.1에 둘 다 넣고, 같은 리듀서에서 `policy: 'hard' | 'soft'` 플래그로 나눈다. 시간 내 점수와 전체 점수는 두 모드 모두 계산한다.**
- 교재 기준 DCAT는 영역마다 시간이 따로 있다(공간·도형은 7분 30초). 이 압박은 툴에서만 연습할 수 있다.
- 리스크 렌즈가 걱정한 '자동 제출 시점의 정확성' 문제는 마감 판정을 틱이 아니라 타임스탬프 비교로 하면 사라진다. `sectionEnd.t = deadline`으로 기록하고, `answer.t > deadline`이면 거부한다.

| | 실전(hard) | 연습(soft) |
|---|---|---|
| 일시정지 | 없음 | 있음 |
| 0초 | 영역 자동 종료(`sectionEnd.t = deadline`) → 영역 사이 화면 | 빨간 +mm:ss 카운트업, 계속 답할 수 있음 |
| 마감 뒤 답 | 거부('영역 마감' 알림) | 받되 초과로 표시 |
| 영역 이동 | 다음 영역만, 지난 영역은 잠금 | 같음 |
| 페이스 표시 | 숨김 | ±n |
| 창 닫힘·절전 | 시간이 계속 흐르고 공백을 기록 | 공백 기록, 돌아오면 '공백 n분을 일시정지로 칠까요?' 확인 |
| 결과 | 시간 내 점수 = 전체 점수 | 시간 내 점수와 전체 점수 따로 |

- 기본값은 전체 모의고사와 영역 연습이 실전, 드릴이 연습이다. 시험 전에 연습 모드로 전체 모의고사를 1회 풀어 두면 속도 손실(전체 − 시간 내)을 잴 수 있다.
- 영역을 수동으로 끝내는 것은 확인을 받은 뒤 허용한다. 남은 시간은 이월하지 않는다(`carryOver = false`, 미확인).

### 5.3 영역 사이 화면

- 다음 영역의 이름, 문항 수, 시간, 문항당 페이스를 보여 준다. 첫 영역 전에도 같은 화면이 나와 e-book을 해당 쪽으로 넘길 시간을 준다.
- 실전: `interstitialSec`(기본 15초)이 지나면 자동으로 시작한다(`sectionStart.t = 이전 종료 + 15초`, `auto: true`). '지금 시작'을 눌러 바로 시작할 수도 있다.
- 연습: '시작' 버튼으로만 시작한다.
- e-book을 넘길 틈은 주지만, 그 틈이 휴식이 되어 실전 압박이 사라지지 않게 한다.

### 5.4 재개·절전·창 닫힘

- 모든 동작 직후 세션을 저장한다.
- 앱이 열려 있는 동안 5초마다 `kv.owner = {windowId, at}`를 쓴다. 이 하트비트는 창 잠금(§12)과 마지막 생존 시각을 겸한다.
- `advance(s, now)`는 순수한 따라잡기 루프다. 모든 동작·틱·부팅 때 가장 먼저 실행한다.
  - 실전에서 마감이 지난 영역은 마감 시각에 닫는다.
  - 자동 시작 시각이 지난 영역 사이 화면은 그 시각에 시작한다.
  - 마지막 영역이 닫히면 '채점 대기'로 넘긴다.
- **공백 감지**
  - 부팅할 때 `now − 직전 owner.at > 120초`이면 `gap{cause: 'closed'}`를 기록한다.
  - 실행 중 틱 간격이 120초를 넘으면 `gap{cause: 'sleep'}`을 기록한다.
  - 기준을 120초로 둔 이유: 창이 가려지면 스로틀링 때문에 틱이 최대 약 60초까지 늦을 수 있다(추론). 이를 절전으로 잘못 보지 않으려는 것이다.
- **공백 처리**
  - 실전: 시간이 그대로 흐른다. `advance`로 따라잡는다.
  - 연습: '공백 n분을 일시정지로 칠까요?'를 버튼 두 개로 묻는다. '예'를 누르면 `pauseRange{from, to}` 보정 이벤트를 덧붙인다. 로그는 시간순 추가만 유지한다.
- v0.2: 실전 중 공백을 '중단'으로 처리할지 묻는 대화상자를 넣는다(리스크 렌즈 제안).

### 5.5 문항 시간(랩)

- 영역 안의 답·해제·⚑ 이벤트를 시간순으로 훑는다. 직전 이벤트(처음에는 영역 시작)부터 이 이벤트까지의 간격에서 일시정지 시간을 빼고, 이 이벤트의 문항에 더한다.
- 같은 문항에 이벤트가 여러 번 있으면 시간을 합친다. 답 변경과 재검토 시간이 여기에 들어간다.
- 공백이 걸친 간격은 그 문항 시간을 `null`로 둔다. 이벤트가 없는 문항도 `null`이다.
- 데이터 렌즈가 제안한 '보류' 버튼은 따로 두지 않는다. ⚑·답·해제가 모두 랩을 닫으므로, 건너뛸 문항은 ⚑를 누르면 된다.
- **일괄 마킹 감지**는 UX 렌즈의 붕괴 가정에 대한 대응이다. 답이 10개 이상이고 답 간격의 50% 이상이 3초 미만이면 그 세션을 '일괄 마킹 의심'으로 표시한다. 이 세션은 문항 시간을 숨기고 정답 정보만 쓴다. 첫 세션 뒤에 한 번 확인한다.

### 5.6 시간 내 점수

- `inLimit(s) = answersAt(영역 s 이벤트, t ≤ deadline(s))`. 마감 시각까지 로그를 재생했을 때의 답안 상태다.
- 영역 초과 시간은 `max(0, sectionEnd.t − deadline)`이다. `answer.t > deadline`이면 초과 응답이다.
- 실전에서는 마감 뒤 답을 거부하므로 시간 내 점수와 전체 점수가 같다.

### 5.7 표시

- 상태바에 영역 남은 시간을 보인다. 60초 이하이면 주황, 초과하면 빨간 +mm:ss다.
- 연습 페이스는 '+2'나 '−3'으로 보인다.
  - `expected = floor(경과 활동 시간 / paceSec)`
  - `delta = 이 영역에서 답한 문항 수 − expected`
- **brain의 '전체 남은 시간'은 상태바에서 뺀다.** 영역 시간은 다른 영역으로 빌려 쓸 수 없어서 행동에 쓸 정보가 아니다. 총 소요 시간과 제한은 결과 화면에 보인다.

홈 ─┬─ 이어하기(진행 중 세션)

### 6.2 홈

- 진행 중 세션 배너(이어하기·중단), '직전 설정으로 시작'(클릭 1번), '새 세션', 채점 대기 목록, 최근 결과 5개(날짜·세트·시간 내/전체 점수)를 둔다.

- 저장소가 비어 있으면 '백업에서 복원' 안내를 띄운다. 다른 Chrome 프로필로 열었을 때를 대비한 것이다.

### 6.3 시작 화면

30초 안에 끝나도록 직전 값을 자동으로 채운다.

1. 프로필: DCAT / LG. 프로필 값의 출처 배지를 함께 보인다.
2. 범위: 전체 모의 / 영역 하나(드롭다운) / 자유 드릴(문항 수 입력, 시간 = 문항 수 × 페이스로 자동 계산, 수정 가능).
3. 모드: 실전 / 연습(기본값은 범위에 따라, §5.2).
4. 세트: 기존 세트(같은 프로필, 최근 순, 시도 번호 자동)나 새 세트(이름, 시작 번호, 번호 방식 '이어서'/'영역마다 1번부터').
5. 기본 유형(선택): 가족 드롭다운(선택한 영역 힌트를 먼저 보임) 또는 새 이름.
6. 시작하면 영역 사이 화면을 거쳐 풀이로 들어간다.

### 6.4 러너 레이아웃

**[충돌] 답 입력과 도구 배치.**
- brain: 현재 문항의 선택지 ①~⑤, 찍음/검토 토글, 이전/다음 버튼, 미니 OMR 그리드로 점프. 도구는 하단 3탭 [계산기|메모|그림판].
- UX 렌즈: 번호+①~⑤+⚑가 한 행인 OMR(7~8행 표시, 답하면 다음 행 강조, 이전/다음 없음). 메모·그림판 탭과 계산기를 늘 함께 두고(계산기는 접기 가능), 영역별 도구 기본값을 자동으로 적용한다.

→ **권고: UX 렌즈안.** 이유는 세 가지다.
1. 문제가 e-book에 있으므로 툴의 '현재 문항' 포인터가 교재와 어긋나면 엉뚱한 번호에 조용히 마킹된다. 행마다 번호가 붙어 있으면 이런 오마킹이 생기지 않는다.
2. 수리 영역에서는 계산기와 메모를 같이 써야 하는데, 3탭이면 매번 탭을 바꿔야 한다.
3. 메모·그림판 탭에 계산기가 붙은 구조는 지금 쓰는 SKCT 툴과 같아서 새로 익힐 것이 없다.

```
┌──────────── 340–480px ────────────┐
│ 수리자료분석 3/5  12:41  미응답 7  +2  ⏸  종료 │ 상태바 40px
├────────────────────────────────────┤
│ 21   ①  ②  ③  ④  ⑤   ⚑            │
│ 22   ①  ②  ●  ④  ⑤   ⚑            │ 번호 행 OMR
│▶23   ①  ②  ③  ④  ⑤   ⚑            │ 7~8행 ≈ 240px
│ …                                   │
├────────────────────────────────────┤
│ [메모] [그림판]                      │ 남는 높이 전부
│                                      │
├────────────────────────────────────┤
│ C   ⌫   ÷   √              [접기]  │ 계산기 ≈ 220px
│ 7   8   9   ×                       │
│ 4   5   6   −                       │
│ 1   2   3   +                       │
│ 0   00  .   =                       │
└────────────────────────────────────┘
```

- 답하면 다음 미응답 행을 강조한다. 스크롤은 강조 행이 창 아래쪽 2행에 닿을 때만 한다.
- 고른 버블을 다시 누르면 답이 지워지고(clear), 다른 버블을 누르면 답이 바뀐다.
- 현재 영역의 문항만 보인다. 지난 영역은 결과 화면 전까지 숨긴다(`backAcrossSections = false`).

### 6.5 키보드·포커스

**[충돌·경미] 답 단축키.** brain은 설정에서 답 단축키를 켤 수 있게 했고, UX 렌즈는 답 단축키를 아예 두지 않았다.
→ **권고: 두지 않는다.** 숫자키의 의미가 포커스에 따라 바뀌면 지금 어느 모드인지 보이지 않아 조용한 오마킹이 생긴다. e-book과 포커스를 오가는 구조라 단축키로 아끼는 시간도 적다.

- 버블, ⚑, 탭 버튼은 포커스를 받지 않는다(`tabIndex=-1`, mousedown에서 `preventDefault`).
- 숫자·연산자·Enter·Esc·Backspace는 메모에 포커스가 있으면 메모로, 아니면 계산기로 간다. 숫자가 답이 되는 화면은 정답 입력 화면 하나뿐이다.
- 수락 기준: 버블을 누른 뒤 Enter·Space·숫자를 쳐도 답이 바뀌지 않는다.

### 6.6 결과 화면

- 머리: 시간 내 점수 x/N, 전체 점수 y/N, 총 소요/제한, 초과 합계, 미응답, ⚑(맞음/틀림).
- 영역 표: 정답/문항/정답률, 시간 내 정답, 문항당 중앙값 초와 페이스 비교, 미응답, ⚑, 초과 시간.
- 느린 문항 Top5(번호·초·정오).
- 문항 표(접기): 번호, 내 답, 정답, ○×, ⚑, 초과, 초, 변경 수.
- 직전에 같은 프로필·범위로 푼 회차와의 차이 Δ.
- 일괄 마킹 의심 세션이면 '답 간격이 대부분 3초 미만이라 문항 시간을 숨김'이라고 표시한다.
- 세트에 정답이 이미 있으면 정답 입력 화면이 채워진 채로 열려 확인만 누르면 된다.

### 6.7 작은 화면 수락 기준

- 420px 폭에서 가로 스크롤이 없다.
- 340×620에서 계산기를 접으면 상태바, OMR, 메모를 모두 쓸 수 있다. 1366px·125% 배율이면 30% 폭이 약 330px이고, 1920px·150% 배율이면 쓸 수 있는 높이가 약 650px이다.

## 7. 도구

### 7.1 계산기

- 키 배열은 SKCT 툴과 같다: `C ⌫ ÷ √ / 7 8 9 × / 4 5 6 − / 1 2 3 + / 0 00 . =`(20키).
- **[충돌·경미]** brain의 `%` 키는 뺀다. 사용자에게 익숙한 배열을 그대로 쓰고, 실전 계산기의 키 구성은 미확인이다.
- 즉시 실행형이다. 연산자 우선순위 없이 Windows 표준 계산기처럼 2+3×4=20이 된다.
- 연산자를 연달아 누르면 마지막 연산자로 바꾼다.
- `√`는 현재 입력값에 적용한다.
- `=`를 반복하면 마지막 연산을 반복한다.
- `÷0`은 '오류'를 띄우고, C나 숫자를 누르면 풀린다.
- 내부 값은 double 그대로 두고 표시만 유효숫자 12자리로 반올림한다. 0.1+0.2는 0.3, 1÷3×3은 1로 보인다. 위 줄에는 진행 중인 식(예: '12 × 3 =')을 보인다.
- 키보드는 메모에 포커스가 없을 때만 받는다. 프로필의 `calcKeyboard = false`이면 키보드를 끈다(실전 계산기가 키보드를 받지 않는다고 확인될 때).

  | 키 | 동작 |
  |---|---|
  | 0–9, `.`, `+ - * /` | 그대로 입력 |
  | Enter, `=` | = |
  | Backspace | ⌫ |
  | Esc, Delete | C |
  | 넘패드 | 위와 같음 |

- 순수 리듀서 `press(state, key)`로 만들어 키 시퀀스 표로 테스트한다.

### 7.2 메모

- 세션마다 textarea를 하나 둔다. 1초 디바운스로 세션 레코드에 저장하므로 새로고침해도 남는다. '지우기' 버튼이 있다.
- **[충돌·경미] 메모·그림판 저장.** 데이터 렌즈는 메모·그림판 내용을 DB에 저장하지 말자고 했고, UX 렌즈는 문항별 스냅샷을 v0.2에 넣자고 했다.
  → **메모 텍스트만 저장하고 문항별 스냅샷은 제외한다.** 메모는 몇 KB라 비용이 거의 없고, 모의고사 중 새로고침해도 계산 중간값을 잃지 않는다.

### 7.3 그림판

- canvas, Pointer Events, `setPointerCapture`를 쓴다. 획은 점 배열(CSS px)로 보관한다.
- `ResizeObserver`가 크기 변화를 감지하면 캔버스를 CSS 크기 × `devicePixelRatio`로 맞추고 모든 획을 다시 그린다. 창을 스냅하거나 크기를 바꿔도 그림이 남는다.
- 도구는 네 가지다.
  - 펜 2색(검정·빨강)
  - 지우개(`destination-out` 획)
  - 전체 지우기('clear' 표시를 남겨 실행 취소할 수 있음)
  - 실행 취소
- v0.1은 획을 메모리에만 두므로 새로고침하면 사라진다. v0.2에서 선택적으로 획 저장과 그림판 크게 보기(OMR 영역까지 확장)를 넣는다.

### 7.4 영역별 도구 기본값

영역이 시작될 때 프로필의 `tools`(계산기 펼침/접힘, 메모/그림판 탭)를 적용한다. 영역 안에서 사용자가 바꾼 설정은 그 영역이 끝날 때까지 유지한다. 가장 약했던 공간추리(1회 2/10)에서 클릭 없이 그림판을 가장 넓게 쓸 수 있다.

## 8. 채점·태깅

### 8.1 정답 입력(v0.1)

- 풀이 때와 같은 행 목록에서 정답 숫자를 이어서 친다. 5개씩 묶어 보이고, 숫자열('31425…') 붙여넣기도 된다.
- 입력 규칙:
  - 공백·쉼표·줄바꿈은 무시한다.
  - `0`이나 `-`는 '정답 모름'으로 보고 채점에서 뺀다.
  - 1~선택지 수 밖의 문자는 위치를 표시한다.
  - 길이가 문항 수와 다르면 알린다.
- 치는 즉시 ○/×를 보인다.
- 정답은 세트에 저장한다. 같은 세트를 다시 풀면 자동으로 채워지고, 정답을 고치면 그 세트의 모든 세션이 다시 채점된다.
- 해설에 정답 일람표가 없으면 해설을 읽으며 한 문항씩 쳐도 된다. 같은 화면에서 그대로 된다.

### 8.2 ⚑의 의미

**[충돌·경미]** brain은 '찍음'과 '검토' 토글을 따로 두고, UX 렌즈는 ⚑ 하나를 '확신 없음(찍음)'으로 쓴다.
→ **권고: ⚑ 하나.** 풀이 중 클릭이 줄고, 뜻이 하나라 분석도 명확하다.
- 맞혔지만 ⚑가 붙은 문항은 '찍어서 맞힘'으로 따로 집계하고 강점의 근거로 세지 않는다.
- 틀렸고 ⚑가 붙은 문항은 오답 이유를 '찍음'으로 자동 분류한다.

### 8.3 유형 태깅

- v0.1: 시작 화면에서 세트 기본 유형 1개를 고른다. 단원 드릴은 이것으로 태깅이 끝난다.

- 수락 기준: 20문항 세트 태깅이 1분 안에 끝난다. 한 번 재 보고 1분을 넘으면 UI를 줄인다.

### 8.4 오답 이유(v0.2)

- 먼저 자동으로 분류한다.
  - 미응답
  - 초과(초과 구간에 답한 오답)
  - 찍음(⚑)
- 남은 오답에만 칩(개념·실수·오독)을 한 번씩 누른다. 선택 사항이고, 세션의 `reasons`에 저장한다.

### 8.5 분류 체계

**[충돌] 분류 깊이와 영역의 관계.**
- brain: 합격시대 잎 노드를 DCAT 섹션 아래에 묶은 임의 깊이의 경로 트리. 깊이별로 롤업한다.

→ **권고: 2단계, 영역과 독립.**

## 9. 합격시대 가져오기(v0.2)

### 9.1 캡처

붙여넣기 칸의 `paste` 이벤트에서 `text/html`(있으면)과 `text/plain`을 받는다. 파싱하기 전에 먼저 `ImportRecord{status: 'raw', parserVersion}`로 저장한다. 그러면 파서가 늦거나 틀려도 원문이 남고, 파서를 고친 뒤 다시 파싱할 수 있다.

### 9.2 파싱 순서

1. `text/html`이 있으면 `DOMParser`로 table의 행과 셀을 읽는다.
2. 없으면 탭 구분 텍스트로 읽는다.
3. 그래도 안 되면 '셀당 한 줄' 형태를 행 단위로 다시 묶는다.
4. 마지막으로 줄 끝의 숫자 3개(정답·문제·정답률)를 정규식으로 찾는다.

헤더는 공백을 허용하는 정규식으로 읽는다.

```
응시회차\s*(\d+)\s*회차
응시일\s*(\d{4})년\s*(\d{1,2})월\s*(\d{1,2})일
순위\s*(\d+)\s*위\s*/\s*(\d+)\s*명\s*\(\s*(\d+)\s*%\s*\)
소요시간\s*(\d+)\s*분\s*/\s*(\d+)\s*분
점수\s*([\d.]+)\s*/\s*(\d+)\s*점
맞은\s*개수\s*(\d+)\s*문항\s*/\s*총\s*(\d+)\s*문항
```

- 합계 행은 헤더와 대조한 뒤 뺀다.
- 정답률 열은 응시자 평균일 수도 있다. 정답/문제와 값이 다르면 `rateRaw`에 따로 둔다(소프트 체크).

### 9.3 경로 정규화와 가족 추출

이 규칙은 1회 42행으로 검증했다.

1. NFKC로 정규화하고, 공백을 정리하고, 대시 변형(‐ – — −)을 `-`로 바꾼다.
2. 괄호 `()`와 대괄호 `[]` 바깥(깊이 0)에 있는 `-`에서만 자르고, 조각마다 앞뒤 공백을 지운다. 구분자가 ' - '인지 '-'인지는 미확인이므로 둘 다 받는다.
3. 첫 조각이 `^\d+\.`로 시작하면 대분류(예: '11.추리')로 떼어 속성으로 둔다. 접두가 없는 행은 바로 앞 행의 대분류를 물려받는다.
4. 남은 첫 조각에서 끝의 괄호를 지운 것이 가족이다(예: '자료해석(그래프)' → 자료해석). 나머지 조각이 세부다.
5. 이 규칙을 적용하면 1회 42행이 13가족이 되고 합계 46/75가 맞는다.

### 9.4 체크섬(하드)

- 행마다 정답 ≤ 문제여야 한다.
- Σ문제 = 헤더 총문항(75), Σ정답 = 헤더 맞은 개수(46)여야 한다.
- 헤더가 없으면 경고만 한다.
- 체크가 실패하면 행 편집 미리보기를 띄우거나, '원문만 보관'으로 저장한다.

### 9.5 영역 매핑

**[충돌] 행을 영역에 매핑하는 방법.**
- brain: 경로 접두어 규칙 + 사용자 매핑 기억.
- 데이터 렌즈: 문항 위치(누적 문항 수)만 쓴다.
- 리스크 렌즈 v0.2안: 접두어 규칙(도형추리 → 공간·도형).

→ **권고: 위치 기반.** 교재 사실이 이를 결정한다. '12.공간지각-평면도형-회전/대칭/비교'와 '…평면도형 비교(같은 모양)' 두 행은 도형추리 영역(66–75번)에 속한다. 접두어 규칙을 쓰면 이 두 행이 틀린 영역으로 간다(`exam-facts.md:35`).

1. 행의 문제 수를 누적해 행마다 `qFrom..qTo`를 정한다.
2. 프로필의 영역 경계(DCAT 20/35/55/65/75, LG 20/40/60/80)가 모두 행 경계와 맞는지 검증해 `aligned`를 정한다. 1회는 정확히 맞는다.
3. 경계가 행 중간에 걸리면 그 행은 `sectionId = null`로 둔다. 별칭과 가족의 영역 힌트로 '추론'이라고 표시해 매핑하고 경고한다.

### 9.6 별칭 기억

- 키는 `passsidae|정규화 경로(대분류 제외)`다. 사이트가 행에 접두를 붙이든 안 붙이든 같은 유형은 같은 키를 갖는다.
- 키가 맞으면 자동으로 연결한다. 맞지 않으면 §9.3 규칙으로 가족·세부를 만들어 제안하고 `decidedBy: 'auto'`로 저장한다.
- 이름 변경·병합 UI는 v0.2 후반이나 그 이후에 넣는다. 병합은 별칭이 가리키는 대상을 바꾸는 것으로 처리한다.

### 9.7 미리보기·저장

- 헤더 값, 영역별 합계(예: 15/20 · 12/15 · 11/20 · 2/10 · 6/10), 체크섬 ✓, 새로 생기는 가족 수를 보여 준다.
- 저장하면 `status: 'confirmed'`가 된다.
- 소요 시간이 제한보다 길면 `overtime = true`로 표시한다(1회: 83/65 = 128%).

### 9.8 폴백과 선택안

- 사이트가 복사를 막거나 표를 div·canvas로 그리면, Chrome에서 Ctrl+S '웹페이지, 전체'로 저장한 HTML을 끌어다 놓는다. 같은 DOM 파서로 처리한다.
- 그래도 안 되면 원문만 보관하고 수동 행 편집으로 넘어간다.
- 사이트가 문항별 정오표를 준다면(미확인) 집계 대신 문항 단위로 가져온다. 그러면 시간 공백이 사라진다.
- 선택안(v0.2 이후, 기본은 끔): 합격시대 모의고사를 풀면서 툴에서 같은 문항 수의 연습 세션을 함께 돌리고 답이나 ⚑를 누른다. 그러면 가져온 행의 위치(qFrom–qTo)와 맞춰 행별 시간을 얻을 수 있다(데이터 렌즈). 다만 이중 마킹 부담이 있다.

### 9.9 수락 기준(실제 붙여넣기 픽스처)

- 42행, Σ 46/75.
- 헤더: 1회차, 2026-10-08, 40위/101명(40%), 83/65분, 61.2/100점, 46/75문항.
- 영역 15/20 · 12/15 · 11/20 · 2/10 · 6/10, `aligned = true`.
- 13가족, `overtime = true`.
- 같은 원문을 다시 파싱하면 같은 결과가 나온다(멱등).

## 10. 분석 지표·시각화

### 10.1 v0.1: 결과 화면만

v0.1은 세션 하나의 결과(§6.6)만 보인다. 누적 분석은 v0.2에 넣는다. 늦은 결합 덕분에 v0.1에서 쌓은 세션도 v0.2에서 소급해 분석된다.

### 10.2 분석 단위: 셀

**[충돌] 분석 단위.** brain은 가져온 집계를 합성 문항 레코드로 바꿔 엔진 하나로 처리한다. 데이터 렌즈는 셀(세션 × 영역 × 가족/세부 × 조건)을 단위로 쓴다. 셀에는 n, 정답, 응답 수|null, 시간 내 정답|null이 들어간다.
→ **권고: 셀.** 엔진을 하나로 유지한다는 brain의 목표도 그대로 지킨다.
- OMR 문항은 셀로 합치고, 외부 행은 그대로 셀이 된다.
- 정답률은 셀을 모두 합쳐서 계산한다. 백분율을 평균하면 작은 세션이 과대 반영된다.
- 시간 지표는 랩이 유효한 툴 문항으로만 계산하고, '시간 데이터 38/120문항'처럼 커버리지를 함께 보인다.

### 10.3 지표

| 지표 | 정의 |
|---|---|
| 정답률 p | Σ정답 / Σn |
| 시간 내 정답률 | 툴 세션만(§5.6) |
| 보정 정답률 p̃ | (정답 + k·p영역) / (n + k), k = 4(설정). 가족이 여러 영역에 걸치면 영역 p를 n으로 가중 평균한다 |
| 시간 비율 | 중앙값 초/문항 ÷ 영역 페이스. 평균 대신 중앙값을 써서 막힌 한 문항에 끌려가지 않게 한다 |
| 비중 w | 실전 1회에서 그 가족이 차지하는 문항 비율. 프로필 값이 있으면 그것을 쓰고, 없으면 가져온 모의고사의 빈도(출제자 추정, 미확인), 그것도 없으면 영역 비중을 영역 안 가족 수로 나눈 값 |
| 기대 오답 | w × 실전 문항 수 × (1 − p̃). 실전 1회에서 그 가족 때문에 잃을 것으로 예상되는 문항 수 |
| 분당 득점 | p̃ ÷ (중앙값 초/60) |
| 속도 손실(영역) | 전체 정답 − 시간 내 정답(연습 모드) |
| 미응답·초과·⚑맞힘 비율 | 툴 세션만 |

- **[충돌·경미] 수축 강도 k.** brain은 2, 데이터 렌즈는 4다. → **4(설정값).** 세부 행 대부분이 n≤2라 극단값을 더 눌러 줘야 한다. 예를 들어 전개도 0/6(공간추리 p = 0.2)은 k=4이면 0.08, k=2이면 0.05다.
- 표시 규칙: x/n은 항상 보인다. %는 n≥5일 때만 보이고, n<5는 회색으로 둔다. 판정은 가족 단위로만 한다.
- 뺄 것:
  - brain의 '가족별 최근 3회 추세'(세션이 적어 잡음). 회차 단위 추이만 남긴다.
  - 데이터 렌즈의 80% Wilson 구간. x/n과 수축만으로 표본 크기는 충분히 전달된다.

### 10.4 화면(v0.2)

필터는 프로필, 출처(툴/가져오기), 조건(실전 모의/영역/드릴/외부), 첫 풀이만(판정에서는 기본으로 켬), 최근 N회다.

1. **회차 표**: 날짜, 출처, 조건, 시간 내/전체 점수, 영역별 정답률(CSS 막대), 초과. 시간을 초과한 가져온 기록은 시간 내 칸에 '—(초과 128%)'를 넣고, 시간 내 점수와 같은 축에 놓지 않는다.
2. **영역 표**: x/n, 시간 내 x/n, 중앙값 초와 페이스 비교, 미응답, 초과, 속도 손실.
3. **가족 표**: w, x/n, p̃, 중앙값 초(시간 데이터 n), ⚑맞힘, 기대 오답, 판정. 행을 누르면 세부 유형과 해당 문항 목록(세션·번호)이 펼쳐진다.
4. **산점도**(SVG): x = 시간 비율, y = p̃, 점 크기 = w. 기준선은 y = 1/선택지(0.2)와 x = 1.0이다. 사분면 이름은 강점 / 속도 훈련 / 공부 / 뒤로·찍기다.
5. **판정 카드**: 공부 Top3, 속도 훈련, 실전에서 뒤로 미룰 유형과 찍기 후보. 판정에 미확인 입력값(감점 등)이 쓰였으면 출처를 함께 보인다.

### 10.5 판정 규칙

임계값은 모두 설정값이다.

| 판정 | 조건 | 출처 |
|---|---|---|
| 공부 | 기대 오답 상위 3(n ≥ 3) | brain의 '빈도×(목표−p̃)'에서 목표 = 1, 데이터 렌즈 |
| 속도 훈련 | p̃ ≥ 영역 평균, 시간 비율 ≥ 1.3, 시간 데이터 n ≥ 4 | brain |
| 뒤로(실전 후순위) | 분당 득점 < 영역 평균의 0.6배, 시간 데이터 n ≥ 4, 시간제·첫 풀이 데이터만 | 데이터 렌즈 |
| 찍기 후보 | p̃ ≤ 1/선택지 + 0.1, 감점 없음(미확인 배지) | 데이터 렌즈 |

## 11. 백업·복원

**[충돌] 백업 시점과 복원 방식.**
- brain: v0.1은 수동 내보내기만 둔다. v0.2에 채점 뒤 File System Access로 폴더에 덮어쓰기(불가하면 다운로드)를 넣는다. 복원 방식은 정하지 않았다.
- 리스크 렌즈: v0.1부터 제출할 때마다 자동 다운로드하고, 키 기준 병합 복원(삭제 없음)을 한다.
- 데이터 렌즈: 원자료만 담은 단일 JSON, 교체 복원(복원 전 자동 내보내기), 미백업 배지.

→ **권고: v0.1에 세션 종료마다 자동 다운로드, 미백업 배지, 교체 복원(복원 직전 자동 내보내기)을 넣는다. File System Access와 병합 복원은 v0.2 선택 사항으로 둔다.**
- file:// IndexedDB 영속성이 아직 검증되지 않았으므로 첫 세션부터 백업이 있어야 한다.
- 다운로드는 권한 프롬프트가 뜨지 않는다.
- 교체 복원은 규칙이 단순해 검증하기 쉽고, 직전 자동 내보내기가 실수를 되돌릴 수 있게 해 준다.

형식:

```json
{ "format": "apt-backup", "schemaVersion": 1, "appVersion": "0.1.0",
  "exportedAt": "2026-10-08T21:30:00+09:00",
  "counts": { "sessions": 3, "sets": 2, "imports": 0 },
  "data": { "profiles": [], "sets": [], "sessions": [], "imports": [],
            "taxonomy": [], "aliases": [], "settings": {} } }
```

- 원자료만 담는다: 사용자 프로필, 세트(정답 키·유형 범위), 세션(이벤트 로그·메모), 붙여넣기 원문, 분류·별칭, 설정.
- 파생값은 넣지 않으므로 엔진을 고쳐도 백업과 충돌하지 않는다.
- 내장 프로필은 번들이 원천이므로 넣지 않는다. 세션의 `plan` 스냅샷이 당시 시간 규칙을 보존한다.
- **자동 다운로드**
  - 세션이 결과 화면이나 채점 대기로 넘어갈 때 1회 내려받는다(`apt-backup-YYYYMMDD-HHmm.json`).
  - 사용자 클릭 직후이므로 다중 다운로드 차단에 걸리지 않는다(추론).
  - 설정에서 끌 수 있다.
  - --app 창에서 다운로드 알림이 어떻게 보이는지는 P6에서 확인한다.
- **미백업 배지**: `meta.lastBackupAt` 이후에 바뀐 세션·세트·가져오기의 수를 보인다.
- **복원 순서**
  1. 파일을 고른다.
  2. `validateBackup`으로 형식, `schemaVersion ≤ 앱`, 필수 배열을 검사한다.
  3. `migrate`를 실행한다.
  4. 현재 DB와 파일의 건수를 나란히 보여 준다.
  5. 현재 DB를 자동으로 내보낸다.
  6. `replaceAll` 트랜잭션 하나로 교체한다.
  7. 다시 읽는다.

  잘못된 파일은 거부하고 DB는 건드리지 않는다.
- 부팅 로드와 복원이 같은 `migrate()`를 쓴다. v0.2를 배포하기 전에 v0.1 실제 백업을 마이그레이션 테스트 픽스처로 쓴다.

| 상황 | 처리 | 사용자에게 보이는 것 |

| 시스템 시계 역행 | 마지막 이벤트 시각으로 고정한다 | 없음 |
| 정답 입력 오류 | 잘못된 위치를 강조하고, `0`·`-`는 허용한다 | 인라인 표시 |
| 계산 오류 | ÷0이면 '오류', 아주 큰 수는 지수 표기 | 화면 표시 |

| 앱보다 높은 schemaVersion 데이터(롤백 시) | 쓰기를 멈추고 읽기 전용으로 연다 | '앱이 데이터보다 오래됨' |
| 렌더링 예외 | React ErrorBoundary로 잡는다 | '진행 중 세션은 저장돼 있음, 새로고침' + 내보내기 버튼 |

## 부록 B. 사용자 확인 항목(모두 합쳐 5분 이하)

1. 모니터 해상도와 Windows 배율은? 창 크기 플래그와 패널의 폭·높이 예산이 여기서 정해진다.
2. 지금 SKCT 툴로 풀 때 답은 어디에 적는가? 풀면서 바로 툴에 마킹하는가? 랩 시간 분석의 전제다.
3. 교재 해설에 정답 일람표가 있는가? 출판사는 어디인가? 합격시대와 같은 출판사라면 해설의 유형 표기를 시드로 쓸 수 있다.
4. 합격시대 결과 페이지에서 표를 복사해 메모장에 붙여 넣고, 그 원문을 .txt로 저장해 줄 수 있는가(1분)? v0.2 파서 픽스처이자 보험이 된다.
5. 1회 모의고사를 순서대로 풀었는가? 65분 시점에 몇 번 문항을 풀고 있었는가? 공간추리 2/10의 해석이 여기서 갈린다.
6. 알라딘 뷰어는 PC 앱인가, 웹인가? 툴에 포커스가 있을 때 휠로 쪽이 넘어가는가?
7. (시험 전 아무 때나) 두산 응시 안내나 사전 점검 화면에서 영역 이동, 조기 종료, 시간 이월, 계산기 규칙, 감점을 확인할 수 있는가? 확인되면 프로필 값만 고친다.
